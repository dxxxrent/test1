# FDE 公文生成的业务链路

这是被 Codex 开发和校验的产品流程，可帮助理解本项目的端到端验收对象。它由平台和 CodeBuddy 写作插件协作执行；开发验收需要根据本次改动选择其中受影响的阶段。

```text
用户目标与资料
  → 任务路由与分类
  → 来源清单、资料解析、事实与缺口整理
  → 年度更新按需整理历史基线、变化、预算及服务覆盖
  → 对适用的准备度门禁进行检查，必要时等待用户确认
  → 提纲契约与章节来源映射
  → 起草内容并落实已确认答案
  → 排版生成与对应内容、预算、结构、来源、格式校验
  → 形成带相应状态的候选文档
  → Bridge 登记产物和哈希，提供授权预览/下载
  → 人工审阅；正式交付按适用门禁和人工确认处理
```

具体路径由任务类型决定：模板生成、内容填充、年度更新、审计和参考分析的阶段并不相同。资料不足或事实冲突要保存问题与依据，不能把模型建议直接当作已确认事实。

任务工作区通常包含 `references/`、`_work/`、`output/`、`logs/`。平台负责权限、运行状态、确认、恢复、检索范围和产物登记；专家成员按阶段提交可验证结果，不能自行推进平台状态。

带问题的候选可以用于审阅；运行完成、文件可下载、候选验收通过、正式交付和人工审定是不同结论，报告时保留对应状态。

本包没有复制写作插件、业务模板或用户资料。原项目的主要依据位置：`CODEBUDDY.md`、`CONTEXT.md`、`codebuddy/README.md`、`workspace/codebuddy/README.md`、`docs/architecture/annual-track-gates.md`，以及 `gov-project-intake` 的阶段规则。
