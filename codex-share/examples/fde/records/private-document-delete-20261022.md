# 私有服务建议与需求清单删除验收

项目空间中“我的服务清单建议 仅本人可见”和“我的需求清单 仅本人可见”的文件行增加 `×`。按钮包含文件名的可访问名称，支持键盘操作。沿用现有删除确认，确认中显示文件名；取消不发送删除请求，失败后保留文件并允许重试。

## 权限与数据一致性

- 文件树接口按当前项目权限和用户标记可删除项。仅有编辑权限的本人可删除本人生成的 Word；只读成员、其他成员及其他管理员无法删除他人的私有文件。
- 删除接口只接受本人哈希目录下、指定类型、有效 UUID 和准确 Word 文件名。目录、原始 JSON、任务文件、路径穿越及其他项目文件不能通过此入口删除。
- 后端复用私有文件解析器检查发布记录、归属、实际路径和文件类型，只 unlink 已核验的 Word，不递归删除用户传入的目录。需求清单删除与分析写入使用同一个短时锁。
- 删除后目录、本人交付文件及对应对话轮次同步移除；已打开的预览关闭。旧的下载和预览接口返回 404，刷新后不会恢复已删除文件，也不会把已完成任务重新显示成生成中。
- 其他轮次、申请表及共享资料保持原有内容。内部记录不进入可删除范围；缺少已发布 Word 的完成记录不再提供清单或分析入口。
- 删除请求绑定发起时的项目与用户，切换身份或项目后的响应不修改新页面。
- 项目空间较窄时，文件名占一整行，类型、下载与删除控件置于下一行，避免长文件名被挤成逐字换行。

## 验证范围

构建、前端脚本语法和 Git 差异格式检查通过。`service-recommendations.test.ts`、`workspace-tree.test.ts`、`requirement-analysis-jobs.test.ts` 共 17 项通过，其中包含新增的删除及权限边界。

`service-recommendations-http.test.ts` 和 `requirement-analysis-http.test.ts` 使用独立 PostgreSQL schema、本机 Bridge、真实 Chromium 及模拟模型，覆盖生成、私有下载、预览和删除：

- 服务建议：取消删除、模拟 HTTP 503 后重试、键盘点击 `×`、删除成功关闭缓存预览、交付和对话记录移除、重复删除 404、刷新后仅保留其他轮次。
- 需求清单：从项目空间点击 `×`，删除后本轮从目录和对话移除，详情、下载与预览返回 404，另一轮零项清单仍可下载；刷新后没有遗留的生成中提示。
- 两类清单：跨用户、跨项目、只读身份，以及目录、JSON 和路径穿越边界；桌面 1440×1000、窄屏 390×844，浏览器无未捕获错误。
