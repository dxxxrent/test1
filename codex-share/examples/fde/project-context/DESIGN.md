# Design

## Source of truth
- Status: Active for the multi-user pilot (tier A)
- Last refreshed: 2026-09-22
- Primary product surface: `demo/codebuddy-bridge/public/product.html`
- Architecture decisions: `docs/adr/0009-multiuser-pilot-accounts-and-runner.md`
- Evidence reviewed: Bridge UI/API, permission interview freeze, CodeBuddy headless env-vars, gov-doc-python entry.

## Brand
- Personality: 可信、克制、面向政务工作的专业工作台。
- Trust signals: 明确显示项目、角色、模型、RAGFlow 连接状态、文件解析状态和运行阶段；登录身份可见。
- Avoid: 伪造“已完成”、无来源的政策结论、装饰性导航和遮挡主要内容的弹窗；生产环境演示切号。

## Product goals
- Goals: 单组织内多用户登录协作——项目空间共享资料、按人隔离运行产物、用户级模型偏好、日常按小组组长与小组成员管理项目、平台管理员统一维护知识库；打通写作对话与交付下载。
- Non-goals: 多组织切换、OIDC、ACP 默认、任务容器硬隔离、对象存储、涉密数据、在线 Office 编辑、免审批的自助注册、注册时自选身份、知识库任意人上传、按整组或部门范围自动开放项目。
- Success signals: 未登录不可用；两人同项目可并行写作且产物不串；viewer 不能跑；撤成员立即失效；固定 venv 下文档解析可用。

## Personas and jobs
- Primary personas: 平台管理员、小组组长、小组成员；只读旁听（viewer）仍可作为项目内权限。
- User jobs: 平台管理员建组织和人员并维护知识库；小组组长开户、建项目并勾选或补邀项目成员；小组成员在被选入的项目中上传资料、对话生成、下载同项目产物。
- Key context: 内网试点、非涉密或脱敏、目录隔离（非容器硬隔离）、桌面浏览器优先。

## Information architecture
- Primary navigation: 默认我的项目，平台总览、通知中心和日志管理作为全局入口，日志管理只展示服务端按平台身份判定的可见记录；项目内提供概览、写作流程、资料、交付文件、成员五个页签。管理员保留公共知识库、智能体模型与平台字典管理；MCP 插件与 Skills 目录对全部身份只读可见。
- Auth surfaces: 登录页（含注册申请）；平台管理员的用户管理（审批注册、修改身份）；组织架构（任免小组组长）；站内通知（未读/已读）。
- Core routes/screens: 一个 Bridge 页面，通过 workspace panel 切换；项目、文件、运行和模型数据由 API 提供。
- Content hierarchy: 左侧全局导航；项目页顶部保留项目切换和五个页签；写作页优先显示真实阶段与唯一主要操作，过程文件目录按需展开。

## Design principles
- One surface, one job: 非写作页面不显示聊天输入框或聊天空状态。
- Evidence before completion: 文件状态、模型绑定和运行状态必须来自服务端，不用静态成功文案冒充结果。
- Preserve context: 刷新保留当前项目和页面；历史 SSE 回放不能重新触发已结束的问题卡片。
- Authorize on the server: 前端隐藏按钮只是体验；API 必须按会话用户鉴权。
- Tradeoffs: 保留固定输入区、文件侧栏和真实 API；视觉参考 V2.0，业务状态不由原型演示数据推导。

## Visual language
- Color: 参考公文智能平台 V2.0 的白色侧栏、浅蓝页面底色和蓝色选中态；品牌蓝 #3E8EFF，正文按钮使用 #2468D8 保证白字可读。等待与错误继续使用明确的状态色和文字。
- Typography: 系统无衬线字体；标题高对比，元数据使用小号低对比文本。
- Spacing/layout rhythm: 8px 基础间距；左侧固定 238px（窄屏 220px），右侧控制台 258–280px。
- Shape/radius/elevation: 6–10px 圆角、细边框、轻阴影；避免大面积浮层遮挡内容。
- Motion: 仅使用短暂 toast 和轻微 hover/focus 过渡。
- Imagery/iconography: 导航使用一致的线性 SVG 图标，保留状态点；不引入新图标依赖。

## Components
- Existing components to reuse: `module-nav-item`、`project-card`、`service-badge`、`question-card`、`knowledge-file`、`agent-detail`、`inspector-card`。
- New/changed components: 登录表单、用户管理表、通知列表、平台总览统计卡、项目成员面板、管理员平台默认模型绑定、修改身份对话框、任命小组组长对话框。
- Variants and states: loading、empty、queued/parsing/ready/failed、running/waiting/completed、disabled、unauthorized。
- Token/component ownership: `public/product.css` 维护颜色、间距和布局；`product.js` 只负责状态和 API 绑定。

## Accessibility
- Target standard: MVP 桌面端可键盘操作，按钮使用真实 `button`，状态区域使用 `aria-live` 或可读文本。
- Keyboard/focus behavior: 对话框支持 Esc；取消按钮明确关闭；输入框和模型选择器有可见 focus。
- Contrast/readability: 白色侧栏与浅蓝正文使用深色文字，状态同时提供文字和颜色。
- Screen-reader semantics: 导航使用 `nav` 和 `aria-label`，对话区使用 `aria-live="polite"`。
- Reduced motion and sensory considerations: 只使用短过渡，不使用持续动画。

## Responsive behavior
- Supported breakpoints/devices: 桌面优先，宽度小于 1240px 收窄侧栏并隐藏非核心顶部链接。
- Layout adaptations: 页面本身不滚动；聊天消息、知识库/模型页面和项目列表在各自容器滚动。
- Touch/hover differences: 操作卡片保留清晰边框和按钮，不依赖 hover 才能发现功能。

## Interaction states
- Loading: 顶部服务徽标、RAGFlow 徽标和空列表使用“检查中/处理中”。
- Empty: 总览无项目、项目无资料、知识库无来源、交付无文件均有明确下一步。
- Error: toast 展示可读错误，当前页面和已加载数据不被清空。
- Success: 上传显示已保存/已排队，解析完成显示 RAGFlow 文档 ID 和“知识库已就绪”。
- Disabled: 运行中禁用发送/生成；等待问题时隐藏普通 composer，只显示问题卡片；无权限操作禁用并说明。
- Offline/slow network: 保留当前页面，服务状态降级，不伪造连接成功。
- Unauthenticated: 跳转或展示登录，不加载业务数据。

## Content voice
- Tone: 简洁、具体、可追溯，不把模型推测写成事实。
- Terminology: 使用项目、资料、知识库、解析、角色、模型、运行、交付文件、项目空间、平台身份等术语；角色只指专家团角色，账号的权限级别称为平台身份（定义见 CONTEXT.md）。
- Microcopy rules: 状态文案说明下一步；模型提示词标记“只读”；平台默认模型与既有个人模型设置区分清楚。

## Implementation constraints
- Framework/styling system: 原生 HTML/CSS/JavaScript，Node.js Bridge API；不新增前端框架依赖。
- Design-token constraints: 复用 `product.css` token，将旧操作色映射到 V2.0 白蓝基线。
- Performance constraints: SSE 事件只更新当前活动运行；同项目多用户多 run；历史事件可回放但不重启旧问题状态。
- Compatibility constraints: Chromium/桌面浏览器，Docker Compose（Bridge + Postgres）；RAGFlow 另套；CodeBuddy 无头 + 固定 Python venv。
- Test/screenshot expectations: `npm test`、`npm run build`、登录与权限用例、双用户并行 run、文档解析走 `CODEBUDDY_PYTHON`。

## Open questions
- [ ] 正式生产环境的移动端断点和无障碍等级由业务方确认。
- [ ] 敏感数据上线前是否切换容器 Runner（见 ADR-0005 / ADR-0009）。


## 2026-09-22 交互调整

- 依据：用户提供的 FDE修改0920.docx、公文智能平台V2.0.html，以及项目现行的选库与权限接口。用户进一步确认颜色和说明参照 HTML，现有后端能力必须保留。
- 场景：桌面端项目协作和写作；使用真实项目、成员、文档与运行数据。以表单、卡片、原生对话框和 SVG 关系图表达，动效仅用于状态反馈，尊重 reduced-motion。
- 交互：非管理员总览提供我的项目与我的文档；项目状态与运行状态独立保存；支持状态/标签筛选、卡片编辑与自定义标签。新建默认进行中，本组成员默认全选。
- 写作台：顶部可搜索的项目切换浮层；按项目保留未发送草稿；上传文件旁提供选择知识库。选择弹窗复用既有绑定接口，成员只读；取消新建不修改当前项目的已保存选库。
- 知识库：保留规则、模板、历史、项目、个人五个入口与现行/归档语义；项目资料按项目展开和搜索。公共库固定全部使用，参考项目整项目勾选，个人库使用开关。
- 配置：智能体模型配置仅管理员可用，显示真实主智能体与七个子智能体、可用模型目录。保存平台默认模型，已有个人覆盖继续生效；职责、技能和提示词继续按当前后端能力只读。平台字典维护项目预设标签，删除字典项不移除已有项目标签。
- 组件复用：原有 button、project-card、project-dialog、knowledge-file、agent-detail 和文件树；保留上传、解析、SSE、问题确认、停止运行、产物预览与下载接口。
- 本次未扩展的后端能力：公共/个人库三级目录、自定义公共分类、直接跨组邀请、提示词/技能/工具在线编辑。原型中这些操作仅修改内存，正式页面保持现有业务规则，不展示虚假的保存成功。
- 验证：浏览器覆盖 1440px、375px 与 812px 横屏，检查筛选、创建与刷新、取消选库、草稿隔离、只读权限、模型关系图、字典保存、键盘退出和减少动态效果。另覆盖延迟返回隔离、邀请成员后刷新和默认模型保存。项目元数据与本人文档统计使用独立单元测试，检查并发字段更新和继承文件去重。
- 登录页：采用白蓝、网格化的企业身份认证布局，保持 8px 间距和 6–10px 圆角，减少渐变与装饰性文案；账号、密码、验证码和提交状态均提供明确的标签、反馈与键盘焦点。
- 认证页面：登录与注册申请迁移到独立的 `/login` 认证页面，桌面端使用品牌说明区 + 认证表单区的双栏结构，移动端改为表单优先的单栏结构；认证页不叠加工作台背景，也不使用登录弹窗或遮罩。
- 认证导航：未登录访问工作台或业务接口返回未认证时，跳转到认证页面并保留 `returnTo`；登录成功后返回原路径，注册申请继续遵循平台管理员审批后才能登录的业务规则。
- 认证视觉验证：覆盖桌面端、移动端、登录/注册切换、验证码刷新、密码显隐、提交中、错误和注册成功状态；页面使用静态界面媒介，动效仅保留短暂焦点、悬停和提交反馈。

## 2026-09-22 项目工作区实施

- 用户确认按项目优先、阶段式写作方案实施。沿用现有蓝白令牌、原生按钮、卡片和对话框，以阶段序列和当前步骤构成主要层级，不增加装饰图片和前端依赖。
- 卡片单击进入；新项目落在概览，有执行记录进入写作，经过校核且有可用文件的任务进入交付。业务状态不参与实际完成判定。项目页切换保留上下文，进入、刷新和选库均不启动模型。
- 最初按 single_step 推进；已由下述“自动推进恢复”覆盖默认交互。问题选项仍需明确提交，停止操作给出处理中反馈并同步后端状态。
- 项目资料、个人库和公共知识管理分开呈现；项目资料可直接上传、预览和下载。不可用产物没有下载按钮。解析失败保留可读错误；DOCX、XLSX 预览明确标注只展示内容。
- 草稿按账号、项目保存在浏览器；只读成员禁用上传和写作。资料、交付或成员接口部分失败会显示不完整提示及重新读取入口，避免把请求失败显示为空数据。
- 视觉验证：1440×1000、375×812、812×375，检查页签、阶段面板、问题卡、预览和表单。主要标题 18–21px；移动端页签和阶段列表可以横向滚动，主内容独立滚动；保留 reduced-motion。
- 验证范围：使用真实前端资源、MemoryStore 接口替身与本地独立验收服务，未写入现有业务服务。真实 PostgreSQL、RAGFlow 和模型联调仍需在部署环境验收；无阶段发布审批或在线 Office 编辑。

## 2026-09-22 自动推进恢复

- 依据：用户要求恢复旧版自动推进，隐藏逐步执行入口，将写作阶段移到项目标题右侧，释放聊天区。
- 默认主操作为“自动生成候选稿 / 继续自动生成”：显式使用 deliverable + candidate，复用已保存进度，跨阶段推进至必要确认、候选稿产出或运行故障；不再每完成一步要求点击。若补充要求明确限制为“只分析、不要生成文件”等，服务端仍尊重较小范围，不强制产出文件。进入、刷新、切换项目均不自动发起运行。
- 保留 advance_stage / single_step 的兼容逻辑并标记为隐藏备用；不新增切换开关，不改变正在运行任务的策略。来源权限、真实回答、停止按钮及正式交付门禁不变。
- 写作页顶部显示紧凑阶段条、状态和唯一主要操作；桌面放在项目切换卡右侧，窄屏上下排列，阶段条可单独滚动。聊天区不再放置大阶段卡，不重复显示运行徽章。
- 候选稿完成显示“候选稿已生成 / 尚未正式交付”，可查看文件；必要问题仍用原确认卡显式提交。启动可携带输入框的补充要求，提交失败保留草稿，成功后才清空对应项目草稿。
- 验证：默认请求不含 advance_stage；从旧单步记录恢复会切到自动策略；候选稿不算正式完成；等待确认、停止、只读和跨项目隔离回归。1440×1000、375×812、812×375 检查顶部定位、无页面横向溢出、主按钮和聊天可达。

## 2026-09-22 控件与操作反馈优化

- 继续以用户提供的公文智能平台 V2.0 HTML 为视觉依据，保留白色卡片、浅蓝背景、蓝色选中态和现有权限边界。按 ui-ux-pro-max 检查键盘、焦点、等待反馈、错误恢复和窄屏布局，不另选设计系统。
- 协作者采用可搜索人员选择器：姓名、账号、平台身份分层展示；桌面输入宽度 360px，浮层按视口自动避让，手机端输入和确认按钮分行。未选择不可提交；加入成功才重置，失败保留选择并提供就地错误。
- 人员选择支持方向键、Enter、Esc、Tab 和点击外部关闭；后台数据未变化时保留搜索节点与焦点。候选加载失败单独提供重试，不显示为正常空列表。
- 普通状态、标签、小组选择仍保留原生语义，统一边框、箭头、字号和蓝色焦点。成员行统一头像、文字层级、授权标记和间距。
- 取消与关闭均为非提交按钮，参考项目搜索的 Enter 不保存表单；标签保存和知识库上传在处理中锁定操作，失败保留表单内容。异步项目切换只在没有后续导航时改变页面与焦点。
- 主要交互面向 Chromium 桌面环境；人员浮层采用 Popover API。测试涵盖 375px 手机、812px 横屏、减少动态效果及延迟响应；不扩展旧浏览器兼容或增加暗色主题。

## 2026-09-23 下拉选择控件

- 用户反馈工作台内多处系统原生下拉菜单观感不统一。主工作台和旧版 V8 演示共用自绘列表弹层；主工作台沿用既有白蓝令牌，并延续身份切换、项目筛选、卡片状态和表单字段各自的尺寸层级。
- 原生 select 保留为表单值和业务事件的数据源；可见触发器与选项弹层提供统一边框、悬停、焦点、禁用、选中反馈，并支持键盘方向键、Home/End、Enter、Esc 和文字首字母定位。
- 多选框及已自绘的模型选择器不受影响。弹层使用 Popover API 进入顶层，兼容工作台滚动区域和原生对话框。

## 2026-09-23 依据核验报告浏览

- 用户反馈高分辨率桌面上报告栏右侧空白过多；报告容器最大宽度扩至 1480px，并随较窄窗口自适应，沿用工作区现有独立滚动容器。
- 分类结果翻页保留当前滚动位置；滚动离开页首后，在视口右下角显示“回到顶部”悬浮按钮，由用户主动点击平滑回到核验工作区顶部。
- 验证：Playwright 在 1920px 桌面宽度确认报告使用可用宽度、翻页保留位置、回顶按钮按滚动状态显隐且点击有效；保留 20 项分页和小屏布局边界。
