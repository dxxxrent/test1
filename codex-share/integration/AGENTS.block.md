## Codex 修改、校验与记录约定

代码需求、修复和界面调整按以下流程执行：
1. 先阅读 `codex-share/WORKFLOW.md`，再读取目标项目适用约定、相关代码和 Git 改动。
2. 理解需求和验收标准 → 必要修改 → 按影响校验 → 复核差异 → 记录和交接。
3. 根据目标项目识别测试入口；文档需求和 UI 变更按适用的配套 Skill 处理。
4. 保留其他任务的未提交改动；失败、跳过、不可用和未运行分别记录，不虚报通过。
5. 实际修改的需求结束前，在现有任务记录中更新证据；没有记录时写入 `docs/testing/`，复杂计划按需放 `docs/plans/`。
6. 只做咨询或只读分析时按请求回答，不创建无关文件。任务范围、适用的项目业务规则和更具体的目录规则决定实现边界。

`codex-share/examples/fde/` 是参考案例，不能作为本项目业务事实或检查命令直接套用。
